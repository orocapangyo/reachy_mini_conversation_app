# Reachy Mini 데스크 동반자(DeskMate) 대화 시나리오 테스트 결과보고서

본 문서는 DeskMate의 대화 기능이 실제 사용 흐름에서 의도대로 동작하는지 검증하기 위해 구축한 시나리오 테스트 체계와 그 수행 결과를 정리한 보고서입니다. 테스트 실행 방법과 시나리오 작성법은 [대화 시나리오 테스트 사용 안내](../scenario-testing.md)를 참고합니다.

| 항목 | 내용 |
| :--- | :--- |
| **테스트 기간** | 2026년 11월 4일 ~ 11월 5일 |
| **테스트 대상** | `desk_companion_ko` 프로필, Gemini Live 백엔드(`gemini-3.8-live`) |
| **테스트 환경** | macOS(Apple Silicon), Python 3.12, MuJoCo 시뮬레이터 |
| **대상 외 범위** | 실물 로봇, OpenAI Realtime 및 Hugging Face 백엔드, 실제 Google Calendar 계정 연동 |

## 1. 결과 요약

시나리오 22종을 구축했으며, 현재 구현된 기능을 대상으로 하는 14종을 실행했습니다. 나머지 8종은 대상 기능이 미구현이거나 실제 계정 준비가 필요하여 본 측정에서 제외했으며, 이 중 끼어들기 후 답변 재개는 현재 동작만 별도로 측정했습니다.

| 구분 | 주요 결과 |
| :--- | :--- |
| **정상 동작 확인** | 일반 도구 호출, 끼어들기 후 새 질문 응답, 수면 → 무응답 → 호출어 기상 → 재수면 흐름 |
| **결함 확인** | 장시간 도구 실행 중 다른 도구의 결과가 모델에 전달되지 않아 응답이 중단되는 결함 1건 |
| **미구현 확인** | 일정 등록, 일정별 준비 사항 추천, 예약 수면, 기상 후 자동 재수면, 끼어들기 후 이전 답변 재개 |
| **추가 확인 필요** | 시뮬레이터 도구 그룹의 실패 6건은 결함 6건을 의미하지 않으며, 원인 분류와 재측정이 필요함(5.3절) |

## 2. 구축 배경 및 목적

### 2.1. 구축 배경

DeskMate는 음성 입출력, LLM 도구 호출, 로봇 모션이 하나의 대화 안에서 함께 동작합니다. 이러한 구조에는 다음과 같은 검증상의 어려움이 있습니다.

* **수동 검증의 한계**: 기능이 늘어날수록 직접 말하며 확인하는 방식으로는 결과를 일관되게 기록하고 비교하기 어렵습니다.
* **모델 응답의 비결정성**: 같은 요청에도 응답이 달라지므로 1회 성공만으로 동작을 보장할 수 없습니다.
* **실행 환경 부담**: 모든 확인에 시뮬레이터를 구동하면 반복 검증 비용이 커집니다.

### 2.2. 검증 목적

* **기술 동작 검증**: 도구 호출이 의도대로 이루어지는지, 끼어들기(Barge-in)가 발생해도 응답을 이어 가는지 확인합니다.
* **실사용 흐름 검증**: 일정 관리와 수면 모드처럼 데스크 동반자로서 실제 사용할 흐름이 동작하는지 확인합니다.
* **미구현 항목 식별**: 시나리오를 먼저 정의하여 구현이 필요한 기능을 명확히 합니다.

### 3.1. 핵심 사용 시나리오

## 4. 테스트 방법

### 4.1. 실행 환경

동일한 시나리오 파일을 세 가지 환경에서 실행하여 환경별로 다른 항목을 검증합니다.

| 환경 | 구성 | 검증 항목 | 검증 불가 항목 |
| :--- | :--- | :--- | :--- |
| **offline** | 가상 모델, 가상 로봇 | 도구 호출 이후의 내부 처리 | 모델의 도구 선택, 응답 품질 |
| **live** | 실제 Gemini, 가상 로봇 | 모델의 도구 선택, 텍스트 입력 기반 끼어들기 | 음성 인식, VAD, 모션 |
| **sim** | 실제 Gemini, MuJoCo 시뮬레이터 및 실행 중인 앱 | 앱 전체 흐름, 모션(육안 확인), 마이크 입력(`--voice`) | 도구 인자, 끼어들기 신호 수신 여부 |

### 4.2. 판정 기준

각 단계는 호출된 도구, 도구 인자, 답변 내 핵심어, 수면·활성 상태, 무응답 여부를 기준으로 자동 판정합니다. 모션은 시험자가 시뮬레이터 화면을 보고 판정합니다.

| 판정 | 의미 |
| :--- | :--- |
| **PASS / FAIL** | 기대 결과 충족 / 미충족 |
| **KNOWN_BUG** | 원인이 확인되어 등록된 결함으로 인한 실패 |
| **PENDING** | 대상 기능이 미구현이거나 사전 준비가 필요하여 실행하지 않음 |

### 4.3. 시나리오 관리

시나리오 1개는 `tests/scenarios/` 아래 TOML 파일 1개로 관리하며, 코드 수정 없이 파일 추가만으로 모든 환경에 반영됩니다. offline 환경은 API 키가 필요 없고 `pytest`에 포함되어 회귀 테스트로 동작합니다.

## 5. 테스트 결과

### 5.1. 요구사항별 결과

| 요구사항 | 결과 | 근거 |
| :--- | :---: | :--- |
| 도구가 의도대로 호출되는가 | 부분 충족 | live 9종 중 8종 통과. 타이머 실행 중에는 결함 D-01로 실패 |
| 끼어들기 시 새 질문에 응답하는가 | 충족 | live, sim 음성 입력 모두 통과 |
| 끼어들기 후 이전 답변을 재개하는가 | 미충족 | live 0/3. 새 질문에만 답하고 종료 |
| 일정 등록 후 조회 | 미구현 | 캘린더 권한이 읽기 전용이며 일정 생성 도구 없음 |
| 일정별 준비 사항 추천 | 미구현 | 일정 등록 기능이 선행되어야 함 |
| 수면 중 무응답 | 충족 | 전 환경 통과 (5.4절의 한계 참고) |
| 호출어 기상 후 음성 명령으로 재수면 | 충족 | sim에서 실제 호출어와 모션까지 확인 |
| 지정 시각 자동 수면 | 미구현 | 스케줄러 없음 |
| 용무 종료 후 자동 재수면 | 미구현 | 수면 시간대 판단 및 자동 복귀 로직 없음 |

### 5.2. 환경별 결과

| 환경 | 그룹 | 실행 범위 | 결과 |
| :--- | :--- | :--- | :--- |
| **offline** | 전체 | 14종 | PASS 12, KNOWN_BUG 2 |
| **live** | 도구 | 9종, 각 2회 | 8종 2/2 통과, `tool_pomodoro_lifecycle` 0/2 |
| | 수면 | 2종, 각 2회 | 2종 2/2 통과 |
| | 끼어들기 | 3종, 각 1회 | `barge_switch`, `barge_stop` 통과, `barge_during_tool` 실패 |
| | 끼어들기 재개 (현재 동작 측정) | 1종, 3회 | `barge_resume` 0/3 |
| **sim** | 도구 | 8종, 각 1회 | PASS 1, FAIL 6, KNOWN_BUG 1 |
| | 수면 | 2종, 각 1회 | PASS 2 |
| | 끼어들기 (음성 입력) | 2종, 각 1회 | PASS 2 |

* live 및 sim 결과는 반복 횟수가 적어 통계적 통과율이 아니라 동작 여부 확인으로 해석해야 합니다.
* `combo_focus_until_meeting`의 live 결과는 테스트 데이터의 일정 시각을 수정한 후 재측정한 값입니다. 수정 전에는 일정이 이미 지난 시각으로 고정되어 0/2였습니다.
* 자동 회귀 테스트(`pytest`) 전체 결과는 561건 통과, 2건 생략, 2건 예상된 실패(결함 D-01)입니다.

### 5.3. 시뮬레이터 도구 그룹 실패 분석

FAIL 6건을 원인별로 분류한 결과는 다음과 같습니다. 본 분류는 실행 로그와 코드 검토에 따른 것이며, 재측정으로 확정되지는 않았습니다.

| 시나리오 | 관찰 내용 | 분류 |
| :--- | :--- | :--- |
| `tool_schedule_today` | 도구 호출 및 일정 답변 정상, 기대 핵심어 없음 | 판정 기준 문제 |
| `tool_schedule_relative` | 도구 호출 및 일정 답변 정상, 기대 핵심어 없음 | 판정 기준 문제 |
| `tool_negative` | 수면 도구 호출 없음, 방송 멘트에 무응답하여 시간 초과 | 판정 기준 문제로 추정 |
| `tool_memory` | 첫 턴 시간 초과, 삭제 턴에 무관한 답변 | 시나리오 간 간섭으로 추정 |
| `tool_parallel` | 도구 2종 호출, 정보를 불러올 수 없다고 답변 | 시나리오 간 간섭으로 추정 |
| `tool_motion` | 도구 호출, 머리가 회전하지 않고 턴 시간 초과 | 원인 미확인 (D-02) |

**시나리오 간 간섭 추정 근거**: sim 환경은 모든 시나리오가 하나의 앱 세션을 공유하며, 먼저 실행된 `combo_focus_until_meeting`이 집중 타이머를 실행한 채 종료되어 이후 시나리오에 결함 D-01이 영향을 주었을 가능성이 있습니다. 해당 시나리오 없이 실행했을 때 `tool_parallel`이 통과한 기록이 이를 뒷받침합니다. 다만 이후 실행된 일정 시나리오는 도구 결과를 정상 수신했으므로 이 추정만으로 모든 현상을 설명할 수는 없습니다.

### 5.4. 결과 해석 시 유의 사항

* sim 환경의 일정 답변은 캘린더 미인증 상태에서 제공되는 기본 일정입니다. 실제 Google Calendar 연동은 본 테스트에서 검증하지 않았습니다.
* sim 환경의 끼어들기 PASS는 답변 내용 기준입니다. 끼어들기 신호와 재생 중단 여부는 판정에 포함되지 않습니다.
* sim 환경의 수면 중 무응답은 텍스트 입력 기준이며, 수면 중 일반 발화의 마이크 입력은 별도로 확인하지 않았습니다.
* `combo_focus_until_meeting`은 도구 호출 여부만 판정합니다.
* live 환경의 끼어들기는 텍스트 입력으로 수행되어 VAD 경로를 거치지 않습니다.
* 호출어 기상은 sim 환경에서만 실제로 검증되었으며, offline과 live 환경은 기상 처리 함수를 직접 호출합니다.

## 6. 발견 사항

| ID | 심각도 | 내용 | 영향 | 확인 수준 |
| :---: | :---: | :--- | :--- | :--- |
| **D-01** | 높음 | 실행 중인 도구가 있으면 다른 도구의 결과를 모델에 전달하지 않음 (`gemini_realtime.py`의 `_handle_tool_result`) | 집중 타이머 중 남은 시간 확인과 중단 불가, 도구 실행 중 끼어들면 응답 중단 | 재현 및 원인 확인 (임시 우회 시 실제 API에서 응답 재개) |
| **D-02** | 중간 | 머리 이동 요청 시 모션이 나타나지 않음 | 머리 방향 전환 요청이 수행되지 않음 | 시뮬레이터 1회 관찰, 원인 미확인 |
| **D-03** | 중간 | 방송 멘트 입력 시 `<no speech>{pause}` 자막과 오디오가 출력됨 | 의도하지 않은 음성이 출력될 수 있음 | live 관찰, 실제 음성 출력은 미확인 |
| **D-04** | 중간 | 캘린더 조회 시 현지 시각에 UTC 표기를 붙여 조회 구간이 어긋남 (`calendar_service.py`) | 오전 이른 시간대 일정 누락 가능 | 코드 검토, 실행 검증 전 |
| **D-05** | 중간 | 캘린더 미인증 시 기본 일정을 실제 일정과 같은 형식으로 답변 | 사용자가 미연동 상태를 인지하기 어려움 | sim 답변으로 확인 |
| **D-06** | 낮음 | 수면 진입 시 취침 인사가 출력되지 않음 | 프로필 규칙과 불일치 | live 관찰 |
| **D-07** | 낮음 | 호출어 엔진 미설치 시 경고만 기록되고 기상할 수 없음 | 수면 상태에서 복귀 불가 | 앱 로그로 확인 |

## 8. 결론

시나리오 테스트 체계를 통해 시뮬레이터 없이도 대화 기능을 반복 검증할 수 있게 되었으며, 새로운 시나리오를 파일 추가만으로 확장할 수 있게 되었습니다. 측정 결과 도구 선택, 끼어들기 응답, 수면·기상 흐름은 Gemini 백엔드에서 동작함을 확인했습니다. 반면 장시간 도구 실행 중 응답이 중단되는 결함 D-01과 일정 등록, 예약 수면 등 미구현 기능이 남아 있으며, 이는 데스크 동반자의 핵심 사용 흐름에 직접 관련되므로 우선 해결할 과제입니다.
